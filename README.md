# My Story Hub · 如我所书

私人游戏故事创作与阅读网站的独立前端重构。沿用已确认的 1536 × 1024 美术画布及现有 Supabase 后端，已部署到原 GitHub Pages 地址。

## 运行

需要 Node.js 22 或更新版本及 npm。

```sh
npm ci
npm run build
npm run dev
```

打开 `http://127.0.0.1:4173`，使用现有受邀账号登录。不提供演示账号、公开注册或匿名内容访问。构建后的 `dist/` 可独立部署到 GitHub Pages；CSS 和 SDK 均已打包，运行时不依赖 CDN。

## 结构

```text
src/
  main.js              唯一初始化、登录恢复、Hash 路由与页面生命周期
  config.js            现有 Supabase 地址及 Publishable Key
  core/                最新请求门闩、私人素材缓存、草稿队列、阅读统计
  components/          常驻 App Shell、个人笔记、读者访问管理
  pages/               首页、书架、目录、阅读、创作、反馈、历史、设置
  services/data.js     经真实数据库核对的查询与管理员操作
  styles/              已确认画布的排版规则及统一扩展样式
scripts/               静态构建、本地服务、浏览器测试运行
tests/                 单元测试、浏览器用例、可回滚的真实数据库 RLS 测试
migrations/            已经批准并应用的最小权限补充
docs/                  审计、测试、部署及维护说明
```

选择原生 ES Modules 而未引入 UI 框架：此站规模小，业务结构明确；保留一个常驻 Shell 和明确的页面生命周期即可解决切页闪烁。esbuild 只用于将本地 Supabase SDK 和样式打包，方便静态托管。

## 已实现

- 受邀账号登录、有效会话恢复、错误提示、退出及私人状态清理。
- 首页和书架沿用确认底图与封面；最近更新来自数据库，无虚构正式内容。
- 常驻背景、品牌与导航；分页数据准备完成后替换内容，过期请求不能覆盖新页面。
- 作品、分卷、章节、小节结构；目录、继续阅读、阅读历史。
- 沉浸阅读、前后章、可折叠目录、字体/字号/行距/宽度及三种阅读主题。
- 通过已核对 RPC 保存阅读位置、完成状态及估算有效阅读时间。
- 个人笔记增改删、默认私人、主动分享与取消分享；作者只看到读者主动分享的笔记。
- 创作结构管理、作品信息、私人封面上传、草稿自动保存、字数统计、草稿预览、发布/撤回及版本恢复。
- 按读者查看作品授权、进度、完成章节、最近阅读和有效时长。
- 个人名称与密码修改、受邀账号档案关联、账号启停及作品授权。

账号创建继续通过 Supabase Authentication 完成，浏览器不持有管理员秘密密钥。

## 测试

```sh
npm test
npx playwright install chromium
```

浏览器测试需要本机已有的两张私人素材。将 `STORY_TEST_ART_DIR` 设为含 `story-frame.webp` 和 `genshin-cover.webp` 的目录，再运行：

```sh
npm run test:browser
```

测试拦截网络并使用合成数据，**不会对生产后端写入测试小说或账号**。截图输出到项目上级目录的 `screenshots/`，不会进入源代码仓库。测试报告为 `test-results/browser-results.json`。

真实数据库安全测试另见 `tests/backend-rls.sql`：它使用事务内合成数据、切换实际 PostgreSQL 角色与 JWT 身份进行断言，最后 `ROLLBACK`，不能作为普通前端脚本运行。执行结果及验证边界见 [测试报告](docs/TEST-REPORT.md)。

## 后端与隐私

管理员可通过个人菜单的“读者视角预览”查看读者界面，无需邀请好友。预览只展示已发布的作品结构，关闭笔记、账号、偏好及阅读进度/时长写入，并可随时退出。预览展示所有已发布作品，真实读者仍按各自授权获取内容；它不模拟某位好友的权限或私人记录。刷新页面会退出预览，不修改真实管理员身份、账号或 RLS。

所有已存在的数据、RLS 和私人 Bucket 保留。初次重构的后端补充为经用户明确批准的 `001_optional_admin_upload_and_profile.sql`：管理员仅可向 `story-art/covers/` 新增素材，以及有效用户通过限定 RPC 修改本人显示名称。该迁移**已经应用，不要重复执行**。

封面引用复用真实 `works.cover_url` 字段，存放私人 Bucket 内的相对路径，不存过期 Signed URL。素材通过带身份的 Storage 下载为会话内 Blob，预先解码，切页复用，退出撤销；未登录不下载私人素材。

## 当前验证边界

真实数据库的五种身份、发布、版本、统计及笔记权限已用回滚事务验证。浏览器账号流程使用合成会话验证；未取得用户密码，也未登录用户的真实账号进行端到端验收。请在独立预览用现有账号完成最终登录和美术验收。

发布沿用现有 RPC，再依次公开章、卷、作品；跨请求并非数据库原子事务。失败会保留草稿并提示重试，重试会先核对已发布内容，避免重复保存相同修订。阅读时间采用近似活动估算；不确定的网络失败暂停增量重发，避免重复累计，强行关闭页面可能损失最后一段尚未同步的时间。多设备同时编辑同一小节仍采用最后保存者的草稿；同一页面内的自动保存已串行化。

部署、维护及正式迁移步骤见 [部署说明](docs/DEPLOYMENT.md)。

https://yihang206.github.io/-My-Story-Hub/

## 阅读与登录便利功能

登录后可在首页点击“继续阅读”，恢复到最近可读章节的段落；读完一章后优先继续下一篇正式章节。登录页可分别勾选“记住账号”和“自动登录”，已登录时也能在个人设置中调整。读者在个人设置输入当前密码、新密码和确认密码即可修改初始密码；成功后使用新密码重新登录。

相关实现与验证边界见 [阅读与登录说明](docs/READER-CONVENIENCE.md)。

## 小说结构与内容录入

作品可设置一个放在第一卷之前的独立楔子，不占用卷章编号。章内小标题居中，可选副标题独立保存；正文中的场景分隔线在草稿预览和阅读页一致呈现。目录可直接定位章内小标题，原有阅读位置及下一章功能继续适用。

所有新录入内容默认草稿，只有明确发布后才对授权读者开放。用户确认的目录和长期录入规范见 [内容结构](docs/CONTENT-STRUCTURE.md) 与 [项目工作规则](AGENTS.md)。数据库仅增加作品开篇类型和可选副标题，复用既有 RLS、发布和阅读同步；对应 SQL 见 [结构补充](docs/PROLOGUE-SCHEMA.sql)，已在当前项目应用，不应重复执行。小说正文不保存在此公开仓库。
